AI agent

Decision Desk

Problem: leads came from SAM.gov, Grants.gov, web research, LinkedIn exports and inbound messages. There were too many to review by hand.

Solved: an agent that scores each lead with a confidence level. Code sorts each one into Pursue, Review, Nurture or Skip, and uncertain cases go to a person. The same engine now screens job postings.

Guardrails

How I keep AI accurate

The rules I build into every AI tool. They're where I'd start on the agent standards this role sets.

Every claim gets a source

Answers come from verified material, not the model's memory.

A person approves first

Nothing ships before someone reviews it.

Code makes the final call

The model makes a narrow judgment with a confidence level, and rules decide.

Unsure goes to a human

When confidence is low, the case goes to a person instead of a guess.

Checks before output

Automated checks run on every result before it goes out.

AI touches only what it should

Folder limits, and API keys held on a server relay.

Client data stays with the client

The work runs in the client's own systems.

Rules live in the tool

OSHA citations and face blurring are built in, not left to memory.

First 90 days

Where I'd start

A first pass, to be reshaped by what the team and the Director, CX Product already know.

Days 1–30

Listen and learn

  • Meet everyone on both teams and learn what's working and what's stuck
  • Learn the stack: Service Cloud, Agentforce, Confluence, Bedrock, and how KCS runs today
  • Record baselines for containment, resolution accuracy, escalation rate and CSAT
Days 31–60

Find the gaps

  • Trace the worst agent misses back to the knowledge behind them
  • Agree on one scorecard for knowledge quality and agent quality
  • Build one prioritized backlog across both teams
Days 61–90

Ship and show

  • Fix the top knowledge gaps and add tests that guard them
  • Tighten escalation and launch sign-off rules for agents
  • Report results to Support leadership in plain language
